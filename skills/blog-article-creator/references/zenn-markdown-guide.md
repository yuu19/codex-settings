# Zenn Markdown 執筆ルール

- 正本: [ZennのMarkdown記法一覧](https://zenn.dev/zenn/articles/markdown-guide)
- 確認日: 2026-08-19

この文書は公式ガイドの転載ではなく、記事作成時に判断を誤りやすい Zenn 固有の記法と制約をまとめたものである。仕様と食い違う場合や、ここにない記法を使う場合は公式ガイドを優先する。

yusuke-blog では Zenn 互換の Markdown レンダラーを使用している。記事の表示確認が必要な場合は、対象リポジトリのプレビューでも確認する。

## 見出し

- 本文はアクセシビリティの観点から `##` で始める。これは公式の推奨であり、構文上の必須条件ではない。
- 記事タイトルは frontmatter で管理し、本文に同じタイトルの `#` 見出しを重複させない。

## コードブロック

言語とファイル名を指定するときは `言語:ファイル名` とする。

````markdown
```ts:src/lib/example.ts
export const example = true;
```
````

diff と言語を併用するときは、`diff` と言語名を半角スペースで区切る。ファイル名は言語名の後ろに付ける。

````markdown
```diff ts:src/lib/example.ts
-export const example = false;
+export const example = true;
```
````

diff の各行は、先頭を `+`、`-`、`>`、`<`、半角スペースのいずれかにしないとハイライトされない。

## メッセージとアコーディオン

通常の補足には `message`、特に注意を促す内容には `message alert` を使う。

```markdown
:::message
補足をここに記述する。
:::

:::message alert
警告をここに記述する。
:::
```

折りたたむ補足には `details` を使う。

```markdown
:::details タイトル
折りたたむ内容をここに記述する。
:::
```

要素をネストするときは、外側の開始行と終了行のコロンを内側より1つ増やす。

```markdown
::::details タイトル
:::message
ネストされた内容
:::
::::
```

## 外部コンテンツの埋め込み

- 一般的なリンクカードは、URL だけの行または `@[card](URL)` で埋め込む。
- X、YouTube、GitHub のコンテンツは、対象 URL だけの行を作り、その前後に空行を置く。
- GitHub のテキストファイルは、URL 末尾の `#L1-L3` のようなフラグメントで表示行を指定できる。
- GitHub Gist は `@[gist](GistのページURL)` を使う。特定ファイルだけなら URL に `?file=ファイル名` を付ける。
- X の URL に複数のアンダースコアが含まれ、自動認識が途切れる場合は `@[tweet](ポストのURL)` を使う。
- URL にアンダースコアが含まれてカードとして認識されない場合は `@[card](URL)` を使う。通常のリンクにする場合は `<URL>` で囲む。

## 数式

ブロック数式は `$$` で囲み、正しく埋め込まれないケースを避けるため、ブロックの前後に空行を置く。

```markdown
本文。

$$
e^{i\theta} = \cos\theta + i\sin\theta
$$

続きの本文。
```

インライン数式は `$a \ne 0$` のように記述する。

## Mermaid

Mermaid は言語名に `mermaid` を指定したコードブロックで記述する。次の Zenn 固有制限を守る。

- 1ブロックは2,000文字以内にする。
- フローチャートにおける `&` の使用数は1ブロックあたり10以下にする。
- クリックイベントは無効である。操作を前提とした説明にしない。
- Mermaid 側の破壊的変更や Zenn 側の制限変更により表示が変わる可能性があるため、複雑な図はプレビューで確認する。

## HTMLコメント

HTML コメントは1行で記述する。複数行コメントには対応していない。

```markdown
<!-- TODO: 検証結果を追記する -->
```

## 完了時の確認

- 本文の最上位見出しが `##` から始まっている。
- コードブロックの言語、ファイル名、diff の指定順が正しい。
- `message` と `details` の開始・終了、およびネスト時のコロン数が対応している。
- URL 単独行と数式ブロックの前後に空行がある。
- Mermaid が文字数、`&` の使用数、クリックイベントの制限を満たしている。
- 記法に迷う場合や制限値を再確認する場合は、公式ガイドを参照している。
