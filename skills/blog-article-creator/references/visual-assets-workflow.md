# 記事用の視覚素材ワークフロー

ブログ記事側が視覚素材の目的、掲載位置、保存先、本文との対応を管理し、素材の種類に応じて専用ツールへ処理を振り分ける。

## 責務

- `blog-article-creator`: 必要な素材の判断、出力先、Markdown への挿入、alt text、キャプション、前後の説明を管理する。
- `browser-agent`: ログイン済みまたは公開 Web 画面を操作し、必要な機密情報を撮影時にマスクして PNG を出力する。記事本文や説明用図解は作らない。
- `$diagram-generator-html`: 構成図、処理フロー、比較図、関係図などを HTML で設計し、検査済み PNG と JSON を生成する。認証済みブラウザは操作しない。
- Matplotlib: 数式、観測値、シミュレーション結果など、座標と数値の正確さが必要なグラフを生成する。

## 振り分け

| 必要な素材 | 使用する手段 | 主な成果物 |
| --- | --- | --- |
| 現在の Web UI、設定画面、操作手順 | `browser-agent` | 機密情報を除去した PNG |
| アーキテクチャ、処理フロー、比較、責務、時系列 | `$diagram-generator-html` | HTML、PNG、検証用 JSON |
| 実画面へ説明、矢印、レイアウトを加えた図 | `browser-agent` の PNG を `$diagram-generator-html` へ渡す | 説明付き PNG |
| 関数、分布、時系列、シミュレーション結果 | Matplotlib | 数値に基づく PNG |

実画面を説明用のモックへ置き換えず、説明用図解のために認証済み画面を不要に撮影しない。スクリーンショットだけで十分な場合は、`diagram-generator-html` を追加で通さない。

## 利用可能性の確認

視覚素材を作成する前に、必要なツールが現在の環境で利用できるか確認する。

- `browser-agent` は `command -v browser-agent` と `browser-agent doctor` で確認する。
- `diagram-generator-html` は skill が利用可能であることを確認し、その `SKILL.md` に従ってレンダラーを実行する。
- ツールが存在しない、認証が未完了、または必要なサイト定義がない場合は、勝手にインストールやログインをせず、不足する素材と前提を残課題として明示する。
- レビューだけを依頼された場合はツールで新しい画像を生成せず、必要な素材と改善内容を提案する。

## 実画面を撮影する

1. 対象記事のリポジトリ規約から、最終 PNG の保存先と Markdown からの参照パスを先に決める。
2. 対象サイトと撮影定義を確認する。既存の定義を使えない場合は、画面、必須マスク、注釈、出力先を特定する。
3. ログイン、MFA、パスワード、本人確認、決済、銀行、税務情報の入力はユーザーに引き渡す。認証情報を記事、設定、チャットへ書かない。
4. 対象記事のリポジトリを作業ディレクトリとして `browser-agent capture` を実行する。ファイルとして残す画像に、マスク検査を通らない通常のブラウザ screenshot や PDF を使わない。
5. 必須マスクや読み込み完了の検査が失敗した場合は画像を採用しない。検査を弱める前に撮影定義や画面状態を修正する。
6. 完成 PNG を目視し、個人情報、通知、識別子、秘密値、不要なブラウザ枠や隣接 UI が残っていないことを確認する。

撮影時のマスクは保存される PNG を保護するものであり、ブラウザを操作するエージェントから値を隠すものではない。エージェントにも見せられない情報を含む画面では、専用テストアカウントまたはダミーデータを使う。

## 説明用図解を生成する

1. 図の目的、読者、必須要素、要素間の関係、記事上の保存先を決める。
2. `$diagram-generator-html` を使い、図の種類に対応する参照とテンプレートを読む。
3. browser-agent の画像を素材にする場合は、機密情報を除去して目視確認した PNG だけを渡す。認証状態、Cookie、ブラウザープロファイル、storage state、操作コードは渡さない。
4. companion skill の標準契約に従って HTML、PNG、検証用 JSON を生成し、自動品質検査を回避しない。
5. PNG を目視し、読み順、情報の優先順位、矢印の方向、余白、文字切れ、重なりを確認する。

## 定量グラフを生成する

- 関数やデータの値をコードで再現できる形にし、Matplotlib で描画する。
- 軸、単位、凡例、式、標本期間を本文と一致させる。
- 説明用図解の見た目を優先して、数値関係を手作業の図形へ置き換えない。
- 日本語フォントと出力サイズは [readability-writing-patterns.md](readability-writing-patterns.md) の規則に従う。

## 記事へ組み込む

- 対象リポジトリのアセット配置規約を優先し、ツールのデフォルト出力先をそのまま採用しない。
- 画像の直前で見るべき点を説明し、直後で本文、コード、数式との対応を説明する。
- alt text は画像の目的と主要な関係が分かる内容にし、装飾的な見た目だけを書かない。
- キャプションには、画面名、条件、比較軸、観測時点など、画像の解釈に必要な情報を記載する。
- 本文だけでも手順や結論を理解できるようにし、重要な情報を画像だけへ閉じ込めない。
