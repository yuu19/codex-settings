# スクリーンショット付きマニュアルテンプレート

SaaS のエンドユーザー向けマニュアルを、スクリーンショット付きで作るときの基本テンプレートです。対象機能に応じて見出しは増減してよいですが、流れは読みやすく保つ。

## 推奨構成

```markdown
# [機能名]

## 概要
[この機能が何をするものかを 2〜4 文で説明する]

## この機能でできること
- [できること 1]
- [できること 2]
- [できること 3]

## 利用前に確認すること
- [対象ユーザーや必要な権限]
- [事前設定や必要条件]
- [制限事項]

## [設定する / 利用する / 接続する] 手順
1. [操作 1]

   ![[操作 1] の画面](/manuals/[topic-slug]/01-[step-slug].png)

2. [操作 2]

   ![[操作 2] の画面](/manuals/[topic-slug]/02-[step-slug].png)

3. [操作 3]

   ![[操作 3] の画面](/manuals/[topic-slug]/03-[step-slug].png)

## [変更 / 停止 / 削除 / 解約 / 再開] について
[必要な場合のみ記載]

## 注意点
- [注意点 1]
- [注意点 2]

## よくある質問
### [質問 1]
[回答]

### [質問 2]
[回答]

## 関連ドキュメント
- [関連ページ 1]
- [関連ページ 2]
```

## スクリーンショット付き本文の書き方

### 1. 画像ではなく操作を説明する

画像が読み込まれなくても、本文だけで手順が追えるようにする。

良い例:

- `通知設定` を開きます。
- `保存する` をクリックします。

悪い例:

- 下の画像のとおりに進みます。
- 赤枠の場所をクリックします。

### 2. 意味のある状態ごとに 1 枚を基本にする

画像は、状態の違いや重要な UI を見せるために使う。

例:

- 機能の開始画面
- 入力前のフォーム
- 確認ダイアログ
- 保存後の完了状態
- 警告やエラー状態

### 3. 画像を増やしすぎない

小さなクリックごとに画像を付けると、かえって読みにくくなる。同じ画像で説明できる細かな操作は、1つの手順にまとめる。

### 4. alt text は実用的にする

alt text は画像の内容を端的に表す。

良い例:

- `通知設定画面`
- `接続確認ダイアログ`
- `保存後の完了画面`

悪い例:

- `image1`
- `screenshot`
- `画面`

## 品質チェック

- 本文だけでも手順を追えるか。
- 各画像に説明上の価値があるか。
- 画像 URL が `apps/docs/static/manuals/` の配置と一致しているか。
- 画像の順序が手順の順序と一致しているか。
- 機密情報や個人情報が写っていないか。
